# `ui/`

Эта директория содержит **визуальный и композиционный слой** редактора.

Здесь описывается, как приложение выглядит, как компоненты вкладываются друг в друга и как события маршрутизируются по UI-дереву.

## Роль в архитектуре

`ui/` находится между `application/` и низкоуровневыми Ratatui-виджетами.

- `application/` хранит состояние и принимает решения.
- `ui/` строит дерево компонентов и переводит состояние в визуальное представление.
- `components/` содержат отдельные визуальные блоки.
- `runtime/` не знает о деталях этих компонентов.

## Что должно лежать здесь

Обычно здесь находятся:

- общий `Component` trait;
- корневой `EditorScreen`;
- keymap и описание горячих клавиш;
- архитектурные документы вроде `UI-GUIDE.md`;
- декларации и re-export’ы подмодулей;
- визуальные правила композиции и layout.

## Что не должно лежать здесь

- `EventStream`;
- работа с raw mode и alternate screen;
- файловый I/O;
- шифрование и другие доменные операции;
- бизнес-решения уровня приложения.

## Как это связано с другими слоями

- `ui/` читает данные из `state/`.
- `ui/` генерирует actions для `application/`.
- `ui/` может использовать Ratatui widgets, но не обязан подменять собой слой приложения.

## Практическое правило

Если код отвечает на вопрос **«как редактор выглядит и как UI-компоненты общаются между собой?»**, он должен быть здесь.

## Рекомендуемая организация

```text
ui/
├── README.md
├── UI-GUIDE.md
├── component.rs
├── keymap.rs
├── screen.rs
└── components/
```

## Важное правило

UI должен быть композиционным:

- родитель владеет дочерними компонентами;
- родитель задаёт `Rect`;
- дочерний компонент не знает о соседях;
- визуальные компоненты не должны смешивать свои ответственности.
