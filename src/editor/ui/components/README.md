# `ui/components/`

Эта директория содержит **изолированные визуальные компоненты** редактора.

Каждый модуль здесь представляет один логический UI-элемент, который можно
компоновать в более крупный экран.

## Роль в архитектуре

Компоненты в этой директории являются строительными блоками для `EditorScreen`.

Типичный поток выглядит так:

```text
EditorScreen
  ├── Header
  ├── TextEditor
  └── Footer
```

`EditorScreen` отвечает за общий layout и маршрутизацию событий, а отдельные
компоненты отвечают только за свою часть UI.

## Что должно лежать здесь

Обычно здесь находятся:

- `header.rs`;
- `footer.rs`;
- `text_editor.rs`;
- будущие компоненты вроде dialog / sidebar / status area;
- локальные view-state структуры, если компоненту нужно отдельное состояние;
- component-specific rendering logic.

## Что не должно лежать здесь

- глобальный application state;
- терминальный runtime;
- файловый I/O;
- код, который управляет соседними компонентами;
- бизнес-логика сохранения или завершения приложения.

## Как это связано с общей архитектурой

- Компонент получает данные от `application/` через state/view-state.
- Компонент преобразует ввод в semantic actions.
- Компонент обновляет только своё локальное состояние или состояние, переданное ему родителем.
- Компонент рендерится только внутри своей области.

## Практическое правило

Если код отвечает на вопрос **«как отрисовать и обслужить конкретный UI-блок?»**, он должен быть здесь.

## Дополнительные файлы

Если компонент начинает разрастаться, его можно разбить внутри этой директории:

```text
text_editor/
├── mod.rs
├── scrollbar.rs
└── tests.rs
```

Разделять стоит по ответственности, а не только по количеству строк.
