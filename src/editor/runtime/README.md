# `runtime/`

Эта директория содержит **исполняющий слой** приложения: терминал, цикл событий, обработку асинхронного ввода и выполнение внешних эффектов.

## Роль в архитектуре

`runtime/` — это инфраструктурная оболочка над приложением.

Она делает следующее:

- инициализирует и восстанавливает терминал;
- переводит терминал в raw/alternate mode;
- читает события из `EventStream`;
- передаёт их в `EditorApplication`;
- вызывает `draw` для рендера;
- выполняет эффекты, которые возвращает приложение;
- завершает программу с итоговым результатом.

Схема работы:

```text
terminal/event source -> UiEvent -> application -> Effect -> outcome
```

## Что должно лежать здесь

Обычно здесь находятся:

- `TerminalSession`;
- `EventSource`;
- основной async loop;
- glue-код для `tokio` + `crossterm` + `ratatui`;
- обработка завершения, очистки и восстановления терминала.

## Что не должно лежать здесь

- бизнес-правила редактора;
- знание о конкретных UI-компонентах;
- логика горячих клавиш;
- структура документа;
- отрисовка конкретных экранов.

## Как это связано с другими слоями

- `runtime/` получает готовое приложение из `application/`.
- `runtime/` не должен знать, почему приложение завершилось — только как корректно выполнить effect и вернуть outcome.
- `ui/` предоставляет компоненты и layout, но не управляет терминалом напрямую.

## Практическое правило

Если код отвечает на вопрос **«как читать события, рисовать кадры и безопасно завершать terminal session?»**, он относится сюда.
