# `application/`

Эта директория содержит **уровень приложения**: состояние, обработку действий и правила того, как UI и runtime должны взаимодействовать с редактором.

## Роль в архитектуре

`application/` находится между `runtime/` и `ui/`.

- `runtime/` читает внешние события и передаёт их сюда.
- `ui/` превращает пользовательский ввод в семантические действия.
- `application/` решает, как изменить состояние и какие эффекты запросить.

Иными словами, здесь живёт логика:

```text
UiEvent -> Action -> State update -> Effect / Outcome
```

## Что должно лежать здесь

Обычно здесь находятся:

- корневой `EditorApplication`;
- типы update-цикла;
- преобразование действий в изменения состояния;
- формирование `Effect` и `EditorOutcome`;
- код, который связывает UI-события с состоянием приложения.

## Что не должно лежать здесь

- прямой доступ к терминалу;
- `EventStream` и другие механизмы получения событий;
- отрисовка Ratatui-виджетов;
- файловый I/O без явного эффекта;
- логика конкретных визуальных компонентов.

## Как это связано с другими слоями

- `runtime/` вызывает `EditorApplication`.
- `ui/` описывает визуальную структуру и действия компонентов.
- `state/` хранит данные, которыми управляет приложение.
- `document.rs` и другие доменные типы не должны зависеть от UI.

## Практическое правило

Если код отвечает на вопрос **«что должно произойти в редакторе?»**, а не **«как это нарисовать?»** или **«как прочитать событие из терминала?»**, он, скорее всего, относится сюда.
